# Änderungen in Texten oder Code-Beispielen

du magst Änderungen oder Ergänzungen in Texten der Bauteile oder der Code-Beispiele machen?
sehr gerne -
hier steht wies geht ;-)


## Allgemein

jedes Bauteil hat ein eigenes `Git-Repository` (kurz *repo* ).
dies kannst du dir wie einen Datei-Ordner vorstellen.
Allerdings wird bei einem Git-Repository jede Änderung aufgezeichnet.
Dadurch gibt es eine Historie in der Nachvollzogen werden kann wann welche stelle wie verändert wurde.

um schnell das richtige repo zu finden ist in der gerenderten Seite ganz am Ende mit dem Text `edit source` dieses verlinkt.

Beispiel:
auf der Seite des Grove Buttons:
https://make-your-school.github.io/mks-welcome/part/mks-seeedstudio-grove_button
findest du ganz unten einen link zu
https://github.com/Make-Your-School/mks-SeeedStudio-Grove_Button

zum editieren brauchst du ein Github Account. (kostenfrei)
falls dies für dich keine Option ist schreib bitte über die MYS Mentor*innen Gruppe `Stefan` an.

## Issue

in der github welt ist *issue* die Bezeichnung für *Angelegenheit* / *Fehlerbericht* / *Änderungswunsch*.
und genau das kannst du hier tun:
erzeuge ein neues issue und beschreibe dort was dir aufgefallen ist.

damit können wir alle Auffälligkeiten und Wünsche gut strukturiert sammeln.

## PullRequest

wenn Du direkt eine Idee hast **wie** z.b. eine Formulierung leichter Verständlich ist,
oder du ein issue gefunden hast wo du direkt weißt wie du es lösen würdest,
kannst du diese auch gerne als `PR` (PullRequest) vorbereiten:

- dafür *clone*st du dir das repo. (machst eine Kopie die dann in deinem User-Account *lebt*.)
- passt die `readme.md` oder code-Beispiel in deinem clone an
- und dann empfiehlst du uns diese Anpassungen ins Original zu übernehmen.
    dieses *empfehlen zu übernehmen* nennt sich PullRequest.

aktuell gibt es dazu noch keine ausführliche Dokumentation.

bei der readme.md ist es relative einfach:
dort kann man einfach auf den edit-button clicken und dann führt github einen durch den prozess..
