# Änderungen in Texten oder Code-Beispielen

Du möchtest einen Text in einem Bauteil ändern oder ein Code-Beispiel verbessern? Super – hier erfährst du, wie das geht!


## Grundprinzip

Jedes Bauteil hat ein eigenes `Git-Repository` (kurz *Repo* ).
Ein Repo ist wie ein Ordner, in dem alle Änderungen automatisch gespeichert werden. So kann man jederzeit sehen, wer was geändert hat.

Am Ende jeder Bauteil-Seite findest du einen Link mit „edit source“. Er führt dich direkt zum passenden Repo.

**Beispiel**:
Ganz unten auf der Grove-Button-Seite
https://make-your-school.github.io/mks-welcome/part/mks-seeedstudio-grove_button
findest du den Link zum dazugehörigen Repo:
https://github.com/Make-Your-School/mks-SeeedStudio-Grove_Button

Um etwas zu ändern, brauchst du einen kostenlosen GitHub-Account.
Falls du keinen erstellen möchtest, kannst du Stefan z. B. über die Signal-Mentor*innen-Gruppe kontaktieren.

## Issue anlegen

In GitHub nennt man eine Meldung oder einen Änderungswunsch ein **Issue**.
Wenn dir etwas auffällt, kannst du einfach ein neues Issue erstellen und dort beschreiben, was verbessert werden sollte.

So behalten wir alle Ideen und Probleme übersichtlich an einem Ort.

## Pull Request

Wenn du direkt eine Lösung oder bessere Formulierung hast, kannst du selbst einen **Pull Request** (PR) einreichen.

Das läuft so:

1. Repo forken (eine eigene Kopie in deinem GitHub-Account anlegen)
2. Datei bearbeiten (z. B. die README.md oder ein Code-Beispiel)
3. Änderung einreichen (Pull Request erstellen)

GitHub führt dich Schritt für Schritt durch den Prozess.
Bei der README.md kannst du sogar direkt im Browser auf den Edit-Button klicken – einfacher geht’s kaum.

Aktuell gibt es dazu noch keine ausführliche Dokumentation.
